In this task, I enabled persistence for both the MySQL database and the Nginx configuration using bind mounts. The goal was to ensure that data and configuration files remain intact even after containers are stopped or removed. I configured Docker Compose to mount a local directory for MySQL’s data directory and another local directory for Nginx configuration.

This task involved the most debugging. Initially, database changes were not reflecting as expected. I discovered that editing migration files locally did not affect the running container because the Rails app code had been baked into the Docker image during build. The container was using an older version of the migration file. The solution was to properly use bind mounts for the Rails application directory so that the container reads live files from the host machine. After implementing the bind mount and rebuilding correctly, schema changes were applied as expected. Another issue occurred when Git tried to track the MySQL data directory. Database files should never be committed to version control. I resolved this by adding the data directory to .gitignore.

I verified persistence by inserting records into the database, stopping all containers, restarting them, and confirming that the records still existed. Both MySQL data and Nginx configuration remained intact across container restarts.
